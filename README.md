BR-B에서 제작한 기본 앱을 바탕으로 확장하는 프로젝트입니다. 아래 기존 기능은 구현되어 있으며, 확장 기능은 계획 단계입니다.

| 구분 | 내용 | 상태 |
|---|---|---|
| 기존 | 공격 간격 및 차단 규칙 선택, 논문 결과 재현 | 구현 |
| 기존 | 정상 요청 차단 기록 조회, 결과 JSON 저장 | 구현 |
| 확장 | 정책 A/B 동시 비교 | 예정 |
| 확장 | 브라우저 내 정책 저장·불러오기·삭제 | 예정 |

## 실행 방법

저장소를 내려받아 압축을 모두 푼 뒤 **index.html을 Chrome으로 엽니다.** 별도의 설치, 서버, 로그인, 환경 변수, API 키가 필요하지 않습니다.

```bash
git clone https://github.com/ychanis/lockout-lab.git
cd lockout-lab
```

폴더 안의 `index.html`을 엽니다. 인터넷 연결 없이 기본 계산 기능을 사용할 수 있습니다.

## 사용 방법

1. 공격 평균 간격을 빠름·중간·느림 중 선택합니다.
2. 연속 실패 횟수와 차단 시간을 입력하고 **이 규칙으로 비교**를 누릅니다.
3. **차단된 정상 요청**을 선택해 기록을 확인하거나 **현재 비교 결과 저장**으로 JSON을 내려받습니다.

## 논문 재현 기준

과제10 「로그인 실패 후 일시 차단 정책의 효과와 정상 사용자 차단」의 원본 합성 요청 48,533건을 사용합니다. 단일 계정, 600초 가상 시간, 조건별 30쌍입니다.

5회 연속 실패 후 30초 차단 설정에서 다음 수치가 나옵니다.

| 공격 평균 간격 | 공격 검사 감소율 | 정상 요청 차단율 |
|---|---:|---:|
| 빠름 0.5초 | 91.81% | 92.17% |
| 중간 2초 | 71.30% | 73.83% |
| 느림 10초 | 19.90% | 27.00% |

공격 검사 감소율은 반복별 감소율의 평균입니다. 정상 차단율은 차단된 정상 요청을 제출된 정상 요청으로 나눈 값입니다. 5회·30초는 논문 재현이며 다른 값은 추가 탐색으로 표시합니다.

## 입력 검증

실패 횟수는 1~20회, 차단 시간은 1~300초의 정수만 받습니다. 빈칸·소수·범위 밖 입력에는 안내를 표시하고 마지막 유효 결과를 유지합니다. 복원 버튼으로 논문 기준값을 다시 적용할 수 있습니다.

## 선택적 자동 검증

Node.js 18 이상이 설치되어 있다면 실행합니다. Node.js는 앱 사용에는 필요하지 않습니다.

```bash
node verify.cjs
```

세 조건의 원본 결과 대조, 요청 건수 보존, 차단 시작·종료 경계, 차단 중 시간 연장 없음, 정상 성공 후 초기화와 잘못된 입력을 확인합니다.

## 해석 범위와 데이터

실제 개인정보·계정·비밀번호·API 키를 사용하지 않습니다. 외부 서버에 로그인 요청을 보내지 않습니다. 모든 계산은 브라우저 안에서 이루어집니다.

이 결과는 공격 성공률, 네트워크 트래픽 감소, CPU 성능을 측정한 값이 아닙니다. 정상 접근 손실이 함께 발생하므로 5회·30초를 실제 서비스의 권장값으로 일반화하지 않습니다. 실제 방화벽 연동이나 실시간 이상 탐지는 구현 범위에 포함하지 않습니다.
